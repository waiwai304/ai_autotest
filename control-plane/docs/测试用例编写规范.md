# 测试用例编写规范（v1.0）

> 适用范围：OneBuy 自动化测试平台 `/scenarios/cases/` 页面「新增测试用例」入口。
> 本规范对齐平台现有 7 个用例（public-smoke / full-chain 等）的结构：基本信息 + 步骤清单。
> 按本规范输入文字后，系统自动解析并创建测试用例（保存为**草稿版本**，不影响线上已发布用例）。

---

## 一、用例组成

一个测试用例 = **基本信息**（7 项）+ **步骤清单**（≥1 步）。

### 1. 基本信息字段

| 字段 | 必填 | 规则 | 示例 |
|------|------|------|------|
| 用例名称 | ✅ | 中文，≤50 字 | `商品收藏功能检查` |
| 用例标识 | ✅ | 小写字母/数字/连字符，全平台唯一 | `favorite-check` |
| 用例说明 | ✅ | 一句话说清"测什么、覆盖什么" | `检查商品收藏/取消收藏功能` |
| 测试端 | ✅ | `PC` / `WAP` / `PC+WAP`（双端） | `PC` |
| 需要登录 | ✅ | `是` / `否`（涉及会员数据必须填"是"） | `是` |
| 含写操作 | ✅ | `是` / `否`（下单/支付/收藏等改数据的都算"是"） | `否` |
| 自定义设置 | ⬜ | 可选。格式：`参数名=默认值（说明）`，每行一条 | `keyword=（下单关键词，留空随机）` |

### 2. 步骤清单

每个步骤一行，用竖线 `|` 分段（2~4 段）：

```
步骤编号 | 端 | 操作动作 | 预期结果        ← 4 段（双端用例推荐）
步骤编号 | 操作动作 | 预期结果              ← 3 段（单端用例）
步骤编号 | 操作动作                        ← 2 段（预期可省略，不推荐）
```

| 段 | 规则 | 示例 |
|------|------|------|
| 步骤编号 | 建议格式：`S1`~`S99`（通用）；可扩展前缀：`F1`(前台) `B2`(后台) `W-F1`(WAP前台) | `S1` |
| 端 | `PC` 或 `WAP`（单端用例可省略此段） | `PC` |
| 操作动作 | 口语化描述用户/系统做什么，一句一行，只写一个动作 | `点击商品卡片上的收藏按钮` |
| 预期结果 | 可观察、可判定的结果（看到什么/跳到哪/数值变化） | `出现"收藏成功"提示，按钮变为已收藏状态` |

**步骤编写要求：**
1. 每步只做一个动作，禁止"点击A然后填写B再提交C"混在一步；
2. 预期结果必须可判定（页面元素/文案/跳转/状态），禁止写"一切正常"这类模糊预期；
3. 步骤编号在用例内唯一、按顺序递增；
4. 双端用例需标注每步的端（PC/WAP），单端用例可省略端段。

## 二、完整输入示例

**示例 1：PC 单端只读用例**

```
用例名称：商品收藏功能检查
用例标识：favorite-check
用例说明：检查商品详情页收藏与取消收藏功能是否正常
测试端：PC
需要登录：是
含写操作：否
步骤：
S1 | PC | 打开任意商品详情页 | 页面正常加载，收藏按钮可见
S2 | PC | 点击收藏按钮 | 出现收藏成功提示，按钮变为已收藏
S3 | PC | 再次点击收藏按钮 | 取消收藏成功，按钮恢复未收藏状态
```

**示例 2：双端含写操作 + 自定义设置**

```
用例名称：优惠券下单流程检查
用例标识：coupon-order-check
用例说明：使用优惠券完成下单支付，验证优惠金额正确抵扣
测试端：PC+WAP
需要登录：是
含写操作：是
自定义设置：
keyword=数据线（下单搜索关键词）
步骤：
F1 | PC | 登录会员账号 | 跳转到会员中心
F2 | PC | 搜索关键词并进入商品详情 | 商品详情页正常打开
F3 | PC | 加购并进入确认订单页 | 确认订单页展示商品与应付金额
F4 | PC | 选择优惠券并提交订单 | 优惠金额正确抵扣，订单创建成功
W-F1 | WAP | 重复 F1~F4 流程 | WAP 端同样优惠抵扣成功
```

**示例 3：最简写法（3 段步骤、省略端与预期）**

```
用例名称：首页可访问性检查
用例标识：home-access-check
用例说明：验证首页可正常打开且导航完整
测试端：PC
需要登录：否
含写操作：否
步骤：
S1 | 打开网站首页
S2 | 查看顶部导航 | 导航包含首页/商品/购物车入口
```

## 三、系统处理流程

1. 用户在 `/scenarios/cases/` 页面点击「➕ 新增测试用例」，按规范粘贴文字；
2. 系统逐行解析：`字段：值` 识别基本信息，`步骤：` 之后的 `a | b | c | d` 行识别为步骤；
3. 校验通过 → 创建 `Scenario` + 草稿版本 `ScenarioVersion`（版本 v1，状态=草稿，不进入发起测试列表）；
4. 新用例立即出现在用例说明页列表尾部，带 `📝 页面创建·草稿` 标记；
5. 解析失败 → 页面提示具体哪一行/哪个字段不合法，修正后重新提交。

> **说明**：页面创建的用例为文档级用例（结构化步骤已入库），暂未挂载自动化执行脚本（spec）。
> 后续由开发者将步骤转为 Playwright spec 并发布版本后，即可在「发起测试」中执行。

## 四、常见错误对照

| 错误提示 | 原因 | 修正方法 |
|----------|------|----------|
| `缺少必填字段：用例名称` | 未写 `用例名称：` 行 | 补充该字段行 |
| `用例标识只允许小写字母/数字/连字符` | 标识含中文/大写/空格 | 改为如 `favorite-check` |
| `用例标识已被占用` | 与现有用例重复 | 换一个唯一标识 |
| `测试端必须是 PC / WAP / PC+WAP` | 端字段拼写错误 | 按枚举值填写 |
| `步骤区为空或格式错误` | `步骤：` 后没有合法竖线行 | 每步一行，至少 2 段 `编号|动作` |
| `第N行步骤段数不足` | 竖线分段少于 2 段 | 检查该行竖线分隔 |
| `需要登录/含写操作只允许 是/否` | 填了其他值 | 改为 是 或 否 |
